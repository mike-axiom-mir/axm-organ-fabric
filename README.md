# AXM Organ Fabric

Standalone growth and runtime fabric for AXM organs.

An **Organ** is a reusable internal capability/state structure: something that helps an intelligence or deterministic machine perceive, reason, check, remember, coordinate, repair, create, or otherwise operate. Organs are not Professionals/roles and they are not Hands/external actions.

## Direction

AXM already has organ machinery and organ bodies in existing systems. This repository exists so that organ growth is no longer trapped inside any one host.

The goal is to extract, compare, test, combine, evolve and package organs while preserving source identity, evidence ceilings and compatibility with existing hosts.

- Workshop or WALMI may consume compatible organs from this Fabric when their host adapters exist.
- Mirror and other deterministic machinery may use compatible organs without an AI model.
- AI systems may use the same compatible organs without becoming their owner.
- New hosts may adopt organs through explicit contracts/adapters.

## Current proven donor bodies

### Universal Creation organ body

`intakes/universal-creation-organs/` preserves Universal Creation at donor commit `90148a8cde5349bb4b3801b3256859a631fbf9a6` as two deliberately separate bodies:

- **415 descriptive organ anatomy records**;
- **15 installed executable organ packages**.

The intake contains 433 source files / 325,766 bytes and is byte-verified against the pinned donor. Exact `id@version` identity is checked for executable packages. The Fabric does not promote the 415 descriptions into implementations: the donor's descriptive-versus-executable truth boundary is preserved.

### Collaboration Platform Text Fabric family

`intakes/platform-text-fabric/` preserves **30 committed organ descriptors** plus their donor map/provenance/validation context from Collaboration Platform commit `27757ace6133b243a200b0463e427c8b04d5a8e3`.

Those files are useful real organ anatomy/status bodies, but this intake claims only exact source identity, registry lookup and descriptor integrity. It does not invent an independent execution runtime that the donor did not provide at this boundary.

## Fabric vs archive

`axm-organ-fabric` is the active body: runtime contracts, registries, composition/entanglement, tests, compatibility, organ growth and eventually an Organ Factory.

`axm-organ-archive` is the preservation body. It retains complete recoverable organ code/packages with provenance and categorization, including historical/superseded versions when useful.

The Fabric may learn from the Archive, but growth must not silently rewrite archived source history.

## Fabric vs factory

A future **Organ Factory** is one subsystem inside this Fabric that can discover candidate capabilities, define boundaries, generate or adapt organs, stress-test them, compare variants and package verified outputs.

## Constitutional boundary

Internal AXM merge/canon authority comes from grounded fit to the four roots: Truth, Agency / non-domination, Continuity, and Wisdom before speed. Technical write access is not constitutional authority.
